# Independent synthetic recovery and local audit role

The recovery verifier supports only the two reviewed synthetic fixtures. It authenticates each AES-GCM archive with its distinct context, checks manifest hashes and exact contents, restores ciphertext with exclusive creation, and verifies the restored files. Wrong keys and damaged ciphertext must fail. Intake receipts and replay fingerprints recover together. No business records or decrypted data are written.

`pilot-windows-recovery.ps1 -Root <approved-private-directory> -Mode restore|verify` retrieves a separately approved DPAPI CurrentUser key and passes it to the verifier through a transient anonymous pipe. The key is absent from arguments, environment, reports and plaintext files. The wrapper checks ownership, exclusive user ACLs and reparse points. Respect the device execution policy; do not lower it to run this script. DPAPI requires the original Windows user/profile and device; it does not protect against simultaneous loss of that profile and the cloud account.

Transfer manifests contain exactly two entries (`kind`, `filename`, `sha256`). Archives, verifier and key must already be in the explicitly approved recovery directory. `restore` refuses an existing target, including a partial prior restore. Run `verify` in a new process to retrieve the independently stored key again and authenticate the persisted restored ciphertext. This drill proves a snapshot can be recovered; it does not establish an unattended recurring backup channel.

The Agent Factory's version 4 `pilot-recovery-audit` template is bound to the existing reliability role. Its live entry point accepts only the isolated synthetic pilot identity and fixed local stores. It reads a private, bounded, nonsymlink operator-observed recovery receipt; the receipt is an operator assertion tied to an externally observed drill, not a cryptographic remote attestation. Receipt claims expire after 24 hours or when either snapshot revision changes. Missing, malformed, future, stale or mismatched evidence cannot assert verified recovery. The agent reports HOLD for recurring offsite retention and an authorized business source even after a successful drill. It cannot grant permissions, export keys, send messages or change production.

The pilot invokes the audit after actual storage checks every minute. Its health response withdraws independent recovery claims when critical storage, audit freshness or receipt validity fails. The three public roles keep sharing one bounded website observation. The fourth live role adds local recovery assessment with no additional HTTP traffic or infrastructure.
